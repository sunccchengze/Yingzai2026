## 打开与重建

```bash
# 直接打开
blender 小鹰3D模型/官方三视图版_小鹰/小鹰.blend

# 重新生成（需 bpy；沙箱内先 source 自愈脚本）
source scripts/3d/blenv.sh
python3 scripts/3d/build_xiaoying_v2.py --out /tmp/build/小鹰.blend --samples 12
python3 scripts/3d/calibrate.py --preview /tmp/build/preview   # 出 IoU 与叠图
```

相机：`Camera_Front` / `Camera_Side` / `Camera_Back` / `Camera_ThreeQuarter`；
角色根 `XiaoYing_Root`（旋转它可改姿态）。

## 建模方法

**数据驱动，而非手调参数**：正面图逐行给 X 半宽、侧面图对应行给 Y 半深，
合成椭圆截面环沿 Z 放样。于是渲染出的正/侧剪影与参考图**天然对齐**。
三视图总高不同（610/600/614），行号按包围盒比例互相映射。

配色全部来自像素采样中位数：
白 `#FCF8F2` / 棕 `#6E4D2E` / 黄 `#F6B32A` / 口 `#E25C48` / 眼描边 `#281C0C`。

## ⚠️ 迭代踩坑记录（下一棒务必先读，避免重走）

1. **侧视图前胸是白色，不是棕色。**
   `build_body` 与 `Refs.cy_side` 最初都用 `brown` 掩膜取侧面深度/中心，
   而头部白羽垂下盖住前胸 → 躯干在 Y 向系统性后缩，Δ左端 98% 为正、均值 +25.6px。
   改用 `sil`（剪影）后 side IoU 0.839→0.860。**深度一律取剪影，颜色分界交给材质。**

2. **正面 y517 的 +82px 不是身体造成的。**
   连续三轮试 `taper_ends` 收尾系数、加大平滑窗口、自适应平滑，全部无效。
   核对采样才发现 body 在 y515 拿到 267px（参考剪影 279px）——身体是准的。
   真凶是**翅膀**：下缘锚在 y520，而参考图 y505..530 身体急剧收窄（348→259px），
   翅膀仍贴在体侧最宽处。锚点上提到 y500 后 → +82px 降到 +30px。
   **教训：偏差归因前先验证该部件的采样值，别急着调平滑。**

3. **`taper_ends(bot_frac=...)` 是端点补圈的缩放系数，不是收敛速度**，调它治不了腰身。

4. **IoU 对整体平移不敏感。**
   修正 `cy_side` 基准后 IoU 一点没变——因为所有部件都用 `r.Y()` 换算，
   基准平移会让模型整体移动，而 IoU 按包围盒归一化，平移被消掉。
   （该修正仍保留：它让世界坐标语义正确。）
   **想提分必须改「形状/比例」，不是位置。**

5. **收尾羽会反向拉低分数。** 第 8 轮把 `y_tip` 从 388 收到 376、喙尖抬到 248，
   side IoU 反跌 0.859→0.831，已回退。侧面偏宽 +4.5% 的账**不能记在尾羽头上**。

6. **参考图首末行是抗锯齿残留**（背面 y613 剪影仅 7px 宽），
   会让校准器报出 +230px 假警报。`calibrate.py` 已加边缘噪声剔除。

7. **喙必须按侧视实测脊线放样，不能朝单点收敛。**
   原实现把整个喙收敛到一个 `tip_pt`，做不出鹰喙「上缘先高后钩下」的形，
   side IoU 卡在 0.859 三轮不动。改为从侧视 `yellow` 掩膜逐列分离出上喙的
   上下缘、按 10 段实测剖面放样后，**side 直接 0.859 → 0.927**。

8. **subsurf 会把细长尖端抹圆收缩。** 喙尖横向原留 12%，渲染后整整短了 10 行
   （y260..269 连续 −103px）。尖端保留 26% 才撑得住剪影。

9. **掩膜不含黑描边，需要方向性补偿。**
   `white`/`brown` 掩膜量到的半宽天生比剪影窄约 6px（每侧 3px）。
   但 X 向补 3.2px 是必要的、Y 向补同样多会胖 3.3%——
   逐行统计「参考宽/模型宽」中位数（Y 向只有 0.967）才定得准。

10. **IoU 对「伸出最远端」的改动极其敏感。**
    喙尖前伸到侧视 x=−8、脚中心前移 18px，两次都让 side 从 0.926 暴跌到 0.900。
    因为 IoU 按包围盒归一，最远端一伸长，整体就被压缩。**改形要从内部下手。**

11. **IoU 测不出剪影内部的气质问题。**
    分数到 0.9503 时，渲染图里眼睛却缩成两粒小黑点（参考是招牌大眼）。
    眼在剪影内部，IoU 完全无感。**每轮必须肉眼验收**——
    同类问题还有：尖头顶、倒三角屁股、六颗孤立的脚趾球。

---

12. **喙的观感问题不是 profile 形状，而是「被头遮挡」。**（第21轮，4 次尝试全部记录）
    侧面渲染里喙像一根细长下垂的管子/一片薄弯钩，与参考的粗短三角钩差距明显。
    - 试 ①：按侧视 yellow 实测重写 `beak_profile`（宽度单调递增的下张三角）
      → IoU 0.9506→0.9508，**观感几乎无变化**。
    - 试 ②：`wf` 收窄曲线放缓 + 下缘统一压到 y262..276（喙根厚度 15px→40px）
      → 喙确实变厚，IoU 持平 0.9506，但根部仍看不见。
    - 试 ③：头整体后退 6px 让位 → side **0.9328→0.9197**，且观感没改善。已回退。
    - 试 ④：头按高度分段位移（喙区 −10px、其余 +7px）
      → side 0.9233，且头侧出现**难看的阶梯折角**。已回退。

    - 试 ⑤：喙整体沿 −Y 前移（根 −46px、尖 −18px）使喙根脱出脸外
      → side **0.9328→0.8963**。撞上第 10 条那个坑：最远端一伸长，
      包围盒变大、归一化后整体缩水。已回退。
    - 试 ⑥：在脸上挖喙窝（y196..268 段 Y 半径按余弦窗最深内凹 12%，
      外轮廓最远端不变故不撑包围盒）
      → IoU 0.9495（代价仅 −0.0011），但**喙根仍没露出来**，
      反而在头部右侧边缘压出一道可见凹痕。已回退。

    **evaluated mesh 量测结论**：喙的世界坐标其实是对的
    （侧视 x4..108、行 y206..256、X 宽 122px，与参考 x6..108 / y192..258 吻合），
    但**头的前缘在侧视 x=51，而喙根在 x=108** —— 喙根整段埋在头内部，
    渲染只露出伸到脸外的前端。参考图里头前缘在 x≈74、喙根 x≈108，喙是从脸上长出来的。
    移动头会破坏其他行（试 ③④），前移喙会撑包围盒（试 ⑤），
    局部挖喙窝深度不够、加深则出凹痕（试 ⑥）—— **六条路都堵死了**。

    **下一棒的建议**：不要再在「喙 vs 头」的相对位置上做微调。
    根本矛盾是「侧视剪影要求喙根在 x108（贴着脸）」与
    「渲染要求喙根在头前缘 x51 之外」二者不可兼得，
    说明**头部椭球在喙区的 Y 半径本身就偏大**（脸太鼓，把喙吞了）。
    可考虑：重新提取头部剖面时，在 y196..268 段改用 `sil` 减去 `yellow`
    的掩膜（即扣掉喙占的区域）来采样头的真实轮廓，而不是用 `white`
    ——`white` 在喙根处包含了被喙遮住的脸，导致头被建得过鼓。

13. **隐藏的坐标映射 bug 会让参数调整完全失效。**（第22轮，最重要的一条）
    改了三次 `beak_profile`（重写脊线、加厚到 61px、按逐列实测）喙都还是薄细钩，
    最后才定位到放样代码里：
    ```python
    span = z_top - z_bot   # z_top=r.Z(217), z_bot=r.Z(333) 固定老常量，跨 116 行
    u = (pz - z_bot) / span
    nz = zc + (u - 0.5) * 2.0 * half_z
    ```
    而 `face_pts` 的 pz 实际只落在 y214..272（58 行），于是 u 被压在 0.53..1.0
    的窄区间，`(u-0.5)*2*half_z` 只能取到 half_z 的一小部分 ——
    **profile 里写多厚都被这个映射吃掉**。改用 `face_pts` 自身范围归一后，
    喙立刻变得厚实饱满，有了鹰喙的三角块感。
    **教训：同一个参数连改三次都不动，先怀疑它根本没被用上，而不是继续加大数值。**

14. **按「行」测和按「列」测拿到的是完全不同的形状信息。**
    第21轮按行统计喙的宽度包络，得到「宽度单调递增」，据此建的喙朝左下斜插；
    第22轮改按**列**逐列取上下缘，才看出上缘是一条**先升后降的拱**
    （喙根 y254 → x54~60 隆到最高 y193 → 喙尖回落 y249）——那才是鹰喙的隆起。
    **提取轮廓时，沿哪个轴切片取决于该部件的主延伸方向。**

15. **独立小球堆出来的"羽毛"经不起 Freestyle。**
    想把颈羽做成参考那种大小交替的扇贝波浪，把半径幅度加到 ±26%、下垂 ±55%，
    结果相邻球互相穿插，Freestyle 把**内部交线**也描了出来，背面一片黑色乱线。
    要做扇贝必须换成**单个连续网格**（放样一圈波浪边），不能靠一堆独立球去凑。

16. **冠羽（呆毛）三次改型全部劣化，已回退。**
    原实现是剪影包围盒放样的回转体 + `taper_ends(top_frac=0.15)`，
    渲染像个「奶油尖」，想改成参考那撮向后斜翘、末端分叉的羽毛：
    - 双羽片（半宽 30/24px）→ 太瘦，只剩一个小突起，比奶油尖还弱
    - 加大到半宽 50/40px → 有分量了，但 xoff ±0.1 让两片左右分开像**猫耳朵**
    - 收拢到同一中轴 → 缩成一个小驼峰，更没神
    奶油尖虽不像参考，但至少**挺拔**。下次要做应当沿侧视实测的
    倾斜中轴（x 从 246 偏到 135）放样单片带弧度的羽毛，而不是拼两片直锥。

17. **参考图剖面尺寸 ≠ 模型实际尺寸，贴合类部件必须按 evaluated mesh 建。**
    颈羽披肩首版用 `r.ring(292)` 当上环，它给的是**参考图**剖面 ax=146px，
    而模型头在 y292 的实际 X 半径是 **167px**。披肩因此缩在头里，
    渲染成一团棉花且与头裂开一条缝。
    **凡是要"贴住/盖住"另一个部件的，尺寸都得先量目标部件的求值网格。**

18. **要盖住身体的部件，必须比同高度的身体更宽。**
    披肩裙摆取 150px，而身体 y340 处已 168px、y366 处 185px ——
    整个被身体吞掉，背面只在脖子处露出一小截。
    参考里白羽是**盖在身体外面**的，裙摆放到 196px 才有披肩感。

19. **Freestyle 的 `select_crease` 会把"两个曲面紧贴"和"陡折"都描成线。**
    - 上环只插进头 22px → 披肩壁与头面形成一圈陡折 → 两侧一片黑色乱线。
      对策：上环缩到比头小并插深到 58px，让交界发生在头**内部**。
    - 上环 164px vs 头 167px（只差 3px 近乎重合）→ 正面头侧描边**断续发虚**。
      对策：再收到 128px 拉开间隙。
    **结论：相邻曲面要么明确套叠（差值大），要么彻底藏进去，不能"擦着走"。**

20. **悬空检查：任何"长在"另一部件上的东西，先比对两者的 z 范围。**
    冠羽根部设在行 y46，而头顶最高只到 y60 —— 中间隔着 14px 空气，
    渲染出来是一片浮空的白叶子。根部延伸到 y84 埋进头里才接上。

21. **"分不清"和"太瘦"之间要找折中，别一步走到底。**
    三趾各宽 51px、间距 31px → 重叠 20px，糊成一整块；
    半径收到 17.4px → 变成三根细杆"香肠"，比糊成一团更糟；
    取 22.0px（趾宽 44px、间距 31px，轻微相切）→ 既有肉又分得清。

## 🔑 有效的诊断方法（比反复试参数高效得多）

1. **evaluated mesh 量测**：把 blend 连 subsurf 一起求值，按高度带筛顶点，
   直接量出某部件的真实 Zmin/Ymax，定位缺口归属。
   例：查到上喙 Zmin=1.143 而参考需 1.117；全局 Zmin=0.0418 而参考需 0。
   —— 这比「改参数→渲染→看分数」快一个数量级。

2. **分区比值校正**：按头/身/脚分区统计「参考宽 ÷ 模型宽」的中位数，
   用数据决定缩放系数，而不是猜。单轮即带来 +0.006。

3. **缺肉/多肉分区统计**：`(ref&~got)` 与 `(got&~ref)` 按区累计，
   一眼看出失分主战场。例：侧面头部占缺肉 3671px / 总 7105px，
   而我此前一直在调身体和脚——**方向都错了**。
